# PI 审查的方法


适用：审查他人成果、给执行者找路。本文是 data-reviewer 的私有 skill（prompts/profiles/data-reviewer/skills/pi-review/），程序启用外层审查时随审查者 profile 整篇放进审查操作；其他助手和角色发现不了它。

做法：
1. 把用户的目的拆成它要交的每一项（原文和最新决定里的交付项），逐项对照：这一项现在做出来了吗？没有的，卡在哪一步？
2. 对没做出来的项，读卡住的那一步的实际产物本身，而不是汇总、结论段和图注。先看清它在哪里被挡住，再提意见。
3. 把对方的“做不了、不可靠、已排除、只能固定”都当作对方自己的选择，默认可以翻案。列出对方在这一项上做过的全部选择，逐个追问：换一种选法、反过来、放松、只取其中最好的一部分，或把这个选择当成自由参数让材料自己挑，这一项能不能做出来？对方认为不能动的前提，恰恰是最该先试的。
4. 每个没做出来的项至少给出几条互不相同的路，其中要有被审查者自己不会想到的、敢于推翻对方默认前提的。可以很激进，只要现有材料能做、假设写明。每条意见写明用哪些现有材料、改动哪个选择、预期得到什么，以及它假设了什么。
5. 父级的 handoff 里应指向已试路线记录（成果目录里的文件），先读这份文件；它是待核实的主张：记录里有证据入口、并且你看了确实走不通的路，不重提，把力气放到新路上；只有文字没有证据的“走不通”，照样可以让对方试。
6. 用户说明限制或最新决定的地方，按用户的决定做，不退回去要求理想条件。
